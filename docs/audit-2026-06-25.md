## Résumé exécutif

Fondations **solides** : hexagonal réel (ports = traits purs, domaine sans dépendance technique), sécurité dev-only multicouche, découpage cohérent. Au-dessus de la moyenne pour un outil interne. **6 thèmes transverses** à corriger :

- **T1 — Contention totale du gate MCP** *(défaut le plus impactant)* : le `Mutex gate` est tenu pendant **toute** la boucle de polling de `wait_for_selector` (30 s) et `wait_condition` (60 s) → aucun autre outil ne peut tourner.
- **T2 — Gestion d'erreur silencieuse** : `unwrap_or_default()`, `.ok()`, `let _ = axum::serve(...)`, bind avalé → Claude voit un système en panne comme sain.
- **T3 — Désync doc/code** *(13 constats)* : 12 outils documentés vs 20 réels, adapters absents du diagramme, `--target kwin-eis` non documenté, signatures de traits fictives.
- **T4 — `set_state`/`expose_route` fire-and-forget** : lecture possible d'une valeur périmée juste après écriture (runtime 1-thread).
- **T5 — Duplication structurelle** : 4 `Fallback*`, prologue EIS ×5, `DEFAULT_SDK_URL` ×3, boilerplate JSON ×12.
- **T6 — Tests absents sur les chemins critiques** : `CompositeWaitCondition`, `Fallback*`, reader CDP, erreurs HTTP SDK.

## Constats détaillés

### 🔴 HIGH

**H1 — `click_located` renvoie `success` (isError=false) sur élément absent/invisible** · `adapter-mcp-server/src/lib.rs` `click_located()` ~l.375 · *S · bugs, api*
`{ok:false, reason:"not_found"|"not_visible"}` → `CallToolResult::success` au lieu de `error`. Masque l'échec, peut induire un retry. Incohérent avec `assert_selector`/`wait_condition`.
```rust
if !found {
    let json = serde_json::to_string(&value).unwrap_or_else(|_| "null".to_string());
    return Ok(CallToolResult::error(vec![Content::text(json)]));
}
```

**H2 — Zéro test sur `CompositeWaitCondition` + `Fallback*`** · `deveye-server/src/main.rs` l.483-627 · *M · tests, bugs*
Points d'articulation de l'orchestrateur sans `#[cfg(test)]`. La bascule auto CDP→SDK ne déclenche que sur `PortError::Network` (pas `Timeout` — non vérifié). `wait_until` propage toute `PortError` via `?` au lieu de continuer le polling (discutable, non couvert). Extraire vers `orchestration.rs` + tests : `fallback_triggers_on_network_error_only`, `fallback_does_not_trigger_on_timeout`, `composite_wait_condition_timeout_returns_unsatisfied`, `is_liaison_error_matches_only_network`.

**H3 — `usage.md` annonce 12 outils, réalité = 20** · `docs/usage.md` l.88 · *M · docs*
8 outils livrés absents du tableau (`right_click`, `drag_drop`, `wait_for_selector`, `find_element`, `assert_selector`, `collect_console_errors`, `list_windows`, `wait_condition`) + mise en garde « ne pas invoquer » fausse.

### 🟠 MEDIUM

**M1 — Gate tenu 30-60 s = deadlock de tous les outils** · `adapter-mcp-server/src/lib.rs` `wait_for_selector` l.449 / `wait_condition` l.559 · *M · bugs, async, perf, errors, api, security (7 fusionnés)*
`_serial = self.gate.lock().await` tenu pendant toute la boucle de polling. Fix : ne locker que le temps de l'évaluation atomique *dans* la boucle.
```rust
loop {
    let present = {
        let _serial = self.gate.lock().await;
        self.evaluator.evaluate(&snippet).await.ok()
            .and_then(|v| v.as_bool()).unwrap_or(false)
    };
    if present { return /* found */; }
    if Instant::now() >= deadline { return /* timeout */; }
    tokio::time::sleep(Duration::from_millis(100)).await;
}
```

**M2 — `reqwest::Client` sans timeout (4 adapters SDK)** · `bridge.rs` l.33, `adapter-logs-tracing/lib.rs` l.25, `adapter-commands-http/lib.rs` l.28, `adapter-dioxus-signals/lib.rs` l.36 · *S · security, api, perf (3 fusionnés)*
`Client::new()` sans timeout → un SDK qui répond partiellement fige le gate indéfiniment.
```rust
http: reqwest::Client::builder()
    .connect_timeout(Duration::from_secs(3))
    .timeout(Duration::from_secs(15))
    .build().unwrap_or_default(),
```

**M3 — `set_state`/`expose_route` fire-and-forget** · `deveye-sdk/src/lib.rs` l.224 / l.351 · *S · async, bugs (2 fusionnés)*
Spawn sans await → lecture d'une valeur périmée possible (runtime 1-thread). Fix : `std::sync::RwLock` pour `state`/`routes`, fonctions synchrones.

**M4 — `wait_for_selector` avale les erreurs CDP avec `.ok()`** · `adapter-mcp-server/src/lib.rs` l.464-469 · *M · errors, api*
CDP mort → 30 s d'attente silencieuse → `{found:false}`. Fix : propager `PortError::Network`, tolérer les exceptions JS transitoires.

**M5 — `drain_console_errors` : `unwrap_or_default()` masque les erreurs de parse** · `deveye-server/src/main.rs` l.476 · *S · bugs, errors, api (3 fusionnés)*
Un seul élément non parsé ⇒ `[]` ⇒ « aucune erreur » (l'inverse de l'attendu). En kwin-eis, `Unsupported` propagé au lieu de `[]`. Fix : filtre fine-grained + log + `NoopConsoleErrorSource` en kwin-eis.

**M6 — `window_origin` hardcodé `(0,0)`** · `deveye-server/src/main.rs` l.258 · *M · bugs, api, security (3 fusionnés)*
`KwinEisInteraction::new((0,0))` → clics EIS décalés si la fenêtre n'est pas en (0,0). Fix : résoudre la géométrie via `KwinRenderer` au démarrage + `pub async fn set_window_origin(&self, (i32,i32))`.

**M7 — `architecture.md` : 6 ports doc vs 9 code ; 2 adapters absents** · `docs/architecture.md` l.106, diagramme l.46-48 · *M · docs (4 fusionnés)*
Manquent `ConsoleErrorSource`, `WaitCondition`, `WindowLister` ; `adapter-screencap-kwin` + `adapter-interaction-kwin-eis` absents du diagramme, encore listés « à venir ».

**M8 — `usage.md` : `press_key`/`navigate`/`logs_wait` « à venir » faux** · `docs/usage.md` l.95-107, l.259 · *M · docs*
`logs_wait` n'existe nulle part mais est conseillé en Limitations. Fix : corriger en `wait_condition` / boucle `logs_tail`.

**M9 — `ScreenshotStable` : 2 encodages PNG/itération sous gate** · `deveye-server/src/main.rs` `CompositeWaitCondition::check` l.504-508 · *M · perf, async, errors*
2 captures PNG (multi-Mo) + comparaison byte-à-byte par itération, jusqu'à 60 s. Fix : hash des pixels bruts avant PNG + plafonner `threshold_ms` à 2000.

**M10 — `wire-protocol.md` §3.1 erronée** · `docs/wire-protocol.md` l.122 · *S · docs*

**M11 — `--sdk-url` défaut `localhost`** · `deveye-server/src/main.rs` l.47 · *S · api*

## Points forts à préserver

- **Architecture hexagonale réelle** : ports = traits purs, domaine sans dépendance technique, ajout `--target kwin-eis` sans toucher les ports.
- **Sécurité dev-only rigoureuse** : `init()` no-op intégral en release, bind `127.0.0.1`, `guard_local_host`, `#[forbid(unsafe_code)]` (SDK + MCP), D-Bus session.
- **Gestion connexion KWin** : connexion fraîche par appel, pipe2(O_CLOEXEC) + lecteur avant l'appel D-Bus (deadlock pipe évité), timeout oneshot 4 s.
- **Tests bas niveau** : `build_script`, `parse_geometry`, `bgra_to_rgba`, sérialisations kebab-case, `map_level`.
- **`LazyCdp`** : connexion paresseuse + reconnexion auto → survit aux hot-reloads.
- **Wire protocol versionné** : header `X-DevEye-Protocol-Version` + `PROTOCOL_VERSION` + `wire-protocol.md`.
